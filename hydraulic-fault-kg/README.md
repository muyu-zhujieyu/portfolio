# 作品集｜液压伺服阀故障知识图谱与智能维护平台

**[打开公开交互演示](https://muyu-zhujieyu.github.io/portfolio/hydraulic-fault-kg/)** · 无需安装，使用合成数据展示图谱节点、证据追溯与受约束问答。

> 将公开液压故障资料转化为可追溯、可校验、可用于辅助维修决策的事件知识图谱系统。

## 项目概览

通用大模型可以生成流畅的故障分析，但在工业维修场景中，事实来源、物理机理和建议依据必须能够追溯。本项目围绕液压伺服阀故障演化过程，建立从公开资料解析、三元组与事件抽取、证据锚定、机理校验到图谱问答和维修推荐的完整产品链路。

- 项目类型：AI + 工业知识图谱 + 智能维护决策平台
- 我的角色：产品设计、知识建模、数据流程设计、前后端实现、交互与汇报材料输出
- 交付形态：Vue 管理平台 + FastAPI 服务 + SQLite 数据层 + 中文知识图谱
- 核心原则：模型负责组织表达，关键事实来自图谱、证据片段、机理模板与维修规则

> 作品集版本仅展示公开样例与系统实现，不包含运行数据库、用户上传文件、虚拟环境、大体积原始资料或工程附件。

## 解决的问题

传统故障知识散落在维修手册、论文、教材、产品说明书和历史案例中，存在检索效率低、因果链条不完整、结论难追溯等问题。本项目将非结构化资料转化为结构化故障演化链，并通过机理模板约束问答结果，降低无依据生成对维修决策的干扰。

## 核心体验

- 公开资料登记、解析、清洗与液压领域相关性过滤
- 故障三元组/事件抽取，并锚定原文证据片段
- 同义归一、增量融合与双时态版本记录
- T1-T6 机理模板校验故障链的物理合理性
- ECharts 中文知识图谱、关系筛选与证据追溯
- 基于图谱检索的约束问答与连续追问
- 根据部件、故障模式和异常状态生成维修建议
- 伺服阀曲线样本分析、构建质量指标与后台管理

## 产品设计思路

1. **事实可追溯**：每个核心结论关联来源、段落和证据片段。
2. **推理有约束**：先检索事件链并校验机理，再组织自然语言答案。
3. **流程可观察**：将资料处理、抽取、融合、建图和质量评估完整呈现在界面中。
4. **建议可复核**：维修动作同时呈现触发依据、风险和人工复核提示。
5. **增量可维护**：新增资料作为可选流程，不破坏已有主图谱与版本记录。

## 系统链路

```text
公开资料
  → 文档解析与段落清洗
  → 液压领域过滤
  → 三元组/事件抽取
  → 证据片段锚定
  → 同义归一与增量融合
  → 机理模板校验
  → 图谱节点与关系生成
  → SQLite 持久化
  → 中文图谱展示
  → 约束问答与维修推荐
```

## 功能模块

| 模块 | 主要能力 |
| --- | --- |
| 数据源管理 | 维护公开手册、论文、教材、说明书与故障案例 |
| 抽取与证据 | 领域过滤、三元组抽取、证据片段锚定 |
| 图谱构建 | 归一融合、机理校验、节点关系与事件链生成 |
| 知识图谱 | 中文节点、中文关系、模板筛选与来源追溯 |
| 图谱问答 | 子图检索、证据引用、连续追问与置信度展示 |
| 维修推荐 | 规则匹配、建议排序、风险提示与人工复核 |
| 样本分析 | 伺服阀曲线特征提取与异常结果分析 |
| 质量评价 | 抽取、证据、机理和图谱构建指标监控 |

## 本地运行

### 1. 启动后端

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python init_db.py
uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

后端验收地址：

- API 文档：`http://127.0.0.1:8000/docs`
- 健康检查：`http://127.0.0.1:8000/api/health`

### 2. 启动前端

```powershell
cd frontend
npm install
npm run dev
```

访问：`http://localhost:5173/`

登录页使用演示入口，不代表生产环境认证方案。正式部署时应接入真实身份认证并限制 CORS 来源。

## 环境变量

需要连接兼容接口的大模型时，在后端启动前配置：

```powershell
$env:LLM_API_KEY="your-api-key"
$env:LLM_BASE_URL="https://your-endpoint.example/v1"
$env:LLM_MODEL_NAME="your-model"
```

不要将真实密钥写入代码或提交到 GitHub。
