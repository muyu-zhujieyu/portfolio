# 作品集｜尝尝咸淡 Recipe RAG

**[打开浏览器交互演示](https://muyu-zhujieyu.github.io/portfolio/recipe-rag/)** · 无需密钥，使用自编菜谱模拟查询路由、混合召回与有来源回答。

一个面向中文家常菜场景的模块化 RAG 命令行原型。系统把 Markdown 菜谱转化为结构化知识库，通过向量检索与 BM25 混合召回、元数据过滤、父子文档回溯和查询改写，为“今天吃什么”“某道菜需要什么食材”“推荐几道简单早餐”等问题生成有依据的回答。

> 当前仓库展示的是可公开、可复现的作品集版本：保留核心代码与自编演示数据，不包含原始大规模菜谱、图片、模型缓存、向量索引或 API 密钥。

## 项目目标

普通菜谱搜索依赖关键词，难以理解“简单、清淡、早餐、三人份”等组合意图；直接让大模型回答，又可能编造食材或步骤。本项目尝试把检索质量、回答可追溯性和交互效率放在同一条链路中：

- 支持菜名、分类、难度和自然语言条件的组合查询。
- 以 Markdown 标题感知分块，保留食材、步骤和提示的语义结构。
- 使用向量检索与 BM25 互补召回，再以 RRF 融合排序。
- 回答前回溯完整父文档，减少只取局部片段造成的信息缺失。
- 根据问题类型路由到推荐列表、基础信息或详细做法模板。

## 核心流程

```text
Markdown 菜谱
    ↓ 加载、清洗、元数据增强
父文档 + 标题感知子块
    ↓ BGE 中文向量 + FAISS / BM25
混合召回 + RRF + 元数据过滤
    ↓ 查询分类与改写
父文档回溯 + 上下文组装
    ↓ DeepSeek（OpenAI 兼容接口）
带菜谱依据的中文回答
```

## 模块设计

| 模块 | 职责 | 关键设计 |
| --- | --- | --- |
| `data_preparation.py` | 文档加载、Markdown 分块、元数据增强 | 确定性父文档 ID、菜品分类与难度识别、父子映射 |
| `index_construction.py` | 向量索引构建与本地持久化 | BGE 中文嵌入、FAISS、索引复用 |
| `retrieval_optimization.py` | 检索与排序 | 向量 + BM25 混合召回、RRF、元数据过滤 |
| `generation_integration.py` | 查询理解与回答生成 | 意图路由、查询改写、分场景提示词、流式输出 |
| `main.py` | 端到端编排与命令行交互 | 首次构建/后续加载、错误处理、交互式问答 |

更详细的设计取舍见 [架构说明](docs/architecture.md)。

## 本地运行

建议使用 Python 3.10 或 3.11。在本项目目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

随后编辑 `.env`，填写自己的 `DEEPSEEK_API_KEY`。模型 ID 或兼容接口地址不同的话，也可以修改 `DEEPSEEK_MODEL` 和 `DEEPSEEK_BASE_URL`。

```powershell
python main.py
```

首次运行会下载嵌入模型，并在本地生成 `vector_index/`；后续运行会复用该索引。索引仅应加载自己生成且可信的文件。

## 当前边界

- 当前是命令行产品原型，未提供账号体系、Web UI、会话持久化和运营后台。
- 演示数据用于验证链路，不代表完整菜谱库；回答中的用量、火候和过敏原仍需用户自行核验。
- 真实密钥、虚拟环境、向量索引、模型缓存、原始图片与来源不明确的数据均不进入仓库。
- FAISS 本地索引使用反序列化加载，只应读取本机自行构建的可信索引。
