# 架构与安全说明

## 1. SLAM 与导航分层

### 感知层

G1 内置 MID360 通过 ROS 2 发布点云和 IMU。FAST-LIO 订阅传感器数据，输出局部里程计、累积点云与可保存的 PCD 地图。

### 地图处理层

离线工具读取 PCD，进行高度切片、栅格密度过滤、离群点过滤和障碍膨胀，输出 Nav2 使用的 PGM 与 YAML。原始 PCD 是大体积数据资产，派生栅格图是可审查、可版本化的运行输入，两者分开管理。

### 定位层

v0.1 使用 fixed-start：人工将机器人摆放在约定起点，系统把第一帧稳定 FAST-LIO 位姿对齐到地图位姿。这一方案验证了导航闭环，但不具备任意位置自动重定位能力。

### 规划与执行层

Nav2 先验证目标路径，再执行导航 action。控制输出经过桥接层限幅、自由度约束和方向修正后送往 G1 高层运动接口。到达、失败、STOP 或 EXIT 都必须关闭桥接并执行停止收口。

## 2. 导航状态机

```text
CHECK
  → 雷达 / IMU / Odometry 健康
  → 地图与固定起点确认
READY
  → 接收目标
PLAN
  → 路径不可达：拒绝
  → 路径有效：启用桥接
NAVIGATE
  → 到达：关闭桥接 + stop_move + DONE
  → STOP/异常：关闭桥接 + stop_move + SAFE HOLD
```

桥接默认关闭，只有目标与所有安全条件通过后短时启用。STOP 不依赖普通任务完成流程，应始终可以直接触发。

## 3. 双臂运动分层

`motion_server` 独占手臂控制接口，负责 FSM、关节限位、owner 和控制周期；前台工具通过本地 RPC 完成姿态采集、关节点动、FK/IK、轨迹编译与播放。同一时刻只允许一个 owner 接管，普通退出先将控制权重降为零，紧急路径再进入阻尼状态。

视觉触碰作为上层实验模块，负责 RGB/深度采集、目标检测、深度选点、坐标转换、端点 IK 指标与人工确认，不直接绕过底层运动安全约束。

## 4. 视觉触碰尚需补齐的安全链

1. 从设备读取真实内参、深度尺度和 RGB/Depth 外参并完成几何对齐。
2. 完成相机到机身的 eye-to-hand 标定，以及工具 TCP 的可追溯枢轴标定。
3. 从单端点关节目标升级为连续路径，并加入自碰撞和环境碰撞检查。
4. 设计预接触点与低速末段，接入力/力矩或触觉停止条件。
5. 建立 dry-run、吊架、非接触接近、软目标接触的分级验收流程。

## 5. 公开数据策略

- 可公开：架构、状态机、接口抽象、合成地图、脱敏产品说明。
- 不公开：现场 IP/账号、SSH 脚本、真实 PCD/地图、模型权重、标定文件、执行日志和部署历史。
- 第三方 FAST-LIO、Livox、Nav2 和厂商 SDK 应遵循各自许可证；作品集不重复分发这些源码。
