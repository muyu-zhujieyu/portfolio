# G1 SLAM 导航与安全运动平台 PRD

版本：作品集公开版 1.0

## 1. 产品背景

人形机器人从传感器数据到真实移动，需要同时处理 SLAM、地图生产、定位、路径规划、运动接口和现场安全。只验证单个算法节点无法证明机器人能够稳定完成任务；缺少状态收口和能力边界，也容易把实验功能误用为成熟产品。本项目以“先建立可重复的最小闭环，再逐层扩展”为原则。

## 2. 产品目标

- 在真实 G1 上跑通 MID360、FAST-LIO、二维地图、Nav2 与高层运动接口。
- 支持单会话连续目标导航，并在每个目标后安全停止和回到等待状态。
- 将地图、目标、里程计、桥接和 STOP 组织为可操作的任务状态机。
- 为双臂姿态、轨迹、FK/IK 和视觉触碰提供分层接口与显式安全拒绝。
- 清晰区分已验证能力、实验能力和后续能力。

## 3. 非目标

- v0.1 不支持任意初始位置下的自动重定位。
- 不承诺动态障碍环境中的自主导航和无人看守运行。
- 视觉触碰不等同于经过碰撞规划和力反馈验证的自动接触系统。
- 公开 Demo 不连接机器人、ROS 2、相机、雷达或厂商 SDK。

## 4. 用户与场景

- 机器人算法工程师：验证感知、里程计、地图和 Nav2 接口。
- 机器人工程集成人员：管理启动顺序、节点健康、运动桥接和日志。
- 现场测试人员：执行固定起点摆位、目标任务、STOP 和结果复核。
- 机械臂研发人员：采集姿态、编辑轨迹、预览 FK/IK 和验证工具偏置。

## 5. 核心导航流程

1. 将机器人放置到地图原点附近，并确认朝向。
2. 检查 MID360 点云、IMU、FAST-LIO 节点和 `/Odometry` 新鲜度。
3. 加载经过审核的二维地图，完成 fixed-start 位姿对齐。
4. 输入目标点，先调用路径规划确认可达性。
5. 启用速度桥接，执行 Nav2 导航 action。
6. 到达、失败或人工 STOP 后关闭桥接并执行 `stop_move`。
7. 输出明确状态并回到目标输入，支持下一目标。

## 6. 功能需求与验收标准

### FR-01 初始化健康检查

系统必须检查传感器 topic、FAST-LIO 节点、里程计新鲜度和地图输入。

验收标准：任一关键输入缺失或过期时阻止导航；重复或僵死 FAST-LIO 进程不能被当作健康状态。

### FR-02 固定起点定位

使用者按说明完成原点摆位后，系统将稳定里程计对齐到地图起点。

验收标准：界面明确提示 fixed-start 限制；未确认摆位和静止里程计时不得进入导航状态。

### FR-03 路径预验证

每个目标执行前先计算路径。

验收标准：无路径时保持桥接关闭并返回拒绝原因；有路径时记录目标和规划成功状态。

### FR-04 连续目标导航

单次启动支持依次输入多个目标。

验收标准：每个目标到达后关闭桥接、调用停止接口、输出 DONE 并回到等待状态；下一目标不要求重启全部节点。

### FR-05 STOP 与异常收口

STOP、任务失败和退出都必须触发独立的安全停止路径。

验收标准：速度桥接被关闭，停止命令被调用，状态不再发布新的运动目标；界面显示停止原因。

### FR-06 地图资产管理

系统区分原始 PCD、处理中间图和发布用 Nav2 地图。

验收标准：地图 YAML、PGM、坐标原点和分辨率成对核对；大型 PCD 不进入普通代码仓库；每张发布地图有来源和审核记录。

### FR-07 双臂运动所有权

底层运动服务独占真机接口，上层工具通过 RPC 请求控制。

验收标准：同一时刻只有一个 owner；FSM、关节限位、低状态和控制周期任一条件不满足时拒绝；退出释放控制权重。

### FR-08 视觉触碰安全预演

系统支持手动锁点、端点 IK 指标检查和 dry-run，但在安全链不完整时禁止无人看守执行。

验收标准：IK 不收敛、残差、奇异性、关节余量或跨度超限时 fail closed；页面明确显示缺失的标定、碰撞和接触条件。

## 7. 关键指标

- 初始化成功率与失败原因分布。
- 目标路径规划成功率、任务完成率和 STOP 收口成功率。
- 里程计新鲜度、目标终点误差和连续任务稳定性。
- 地图版本、来源、坐标原点与实机测试结果的可追溯率。
- IK 拒绝率、残差分布、条件数和关节限位余量。

## 8. 主要风险

- fixed-start 摆位误差会直接影响全局目标位置。
- 静态二维地图无法完整描述动态人员、设备和低矮障碍。
- 厂商运动接口、ROS 2 topic 与实际固件状态不一致可能导致控制失败。
- 名义相机外参和工具偏置不能替代真实标定。
- 没有碰撞与力反馈时，视觉目标点不能直接转化为安全接触动作。

## 9. 后续路线

1. 引入 AMCL 或其他全局重定位，并对比 fixed-start 基线。
2. 恢复经过验证的实时障碍层与足迹模型，建立动态场景测试。
3. 建立地图登记、坐标审核和自动化回归数据集。
4. 完成 RGB/Depth、eye-to-hand、TCP 和关节模型的全链路标定。
5. 加入连续笛卡尔路径、碰撞规划和力/触觉停止闭环。
