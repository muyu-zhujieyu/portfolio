# 液压泵近端巡检状态监测平台 PRD

版本：作品集公开版 1.0
产品形态：嵌入式采集 + 数据服务 + Web/PWA 监测客户端

## 1. 产品背景

液压泵试验和现场巡检需要同时确认传感器、采集终端、网络链路及泵运行参数。传统方式依赖分散仪表和人工记录，数据采样时间难对齐、运行变化不易回溯，发生断线时也难以定位问题层级。产品需要建立一条可观察、可核对、可导出的近端数据链路。

## 2. 目标与非目标

### 2.1 产品目标

- 同步展示泄油口温度、泄油口压力、油口 A 压力和油口 B 压力。
- 明确区分浏览器、数据服务、采集终端和数据时效状态。
- 兼顾监控工位宽屏使用与设备近端移动查看。
- 为试验复核提供按时间排列的记录与 CSV 归档能力。

### 2.2 非目标

- 当前版本不自动识别启泵、加载、换向和稳态等工况。
- 不内置特定泵型的报警阈值和故障诊断结论。
- 服务端短期缓存不替代时序数据库或正式数据治理平台。
- 移动 PWA 不作为独立原生应用发布。

## 3. 目标用户

- 液压泵研发与试验人员：观察多通道参数，核对操作阶段和数据范围。
- 质量检验人员：确认编号、通道和记录完整性，导出留档。
- 现场运维与巡检人员：在设备近端查看最新状态，快速定位链路问题。
- 部署调试人员：核对终端连接、报文格式、字段映射和网络端口。

## 4. 核心用户流程

1. 启动数据服务和前端，确认所需端口可用。
2. 终端上电并建立 TCP 连接，页面分别显示服务与终端状态。
3. 用户核对设备编号、传感器位置、通道名称、单位与标定状态。
4. 观察最新时间和接收数量，确认数据持续更新。
5. 在总体趋势和单项趋势中对照现场操作阶段。
6. 通过巡检记录回看具体时刻和四路数值。
7. 任务结束前导出 CSV，核对表头、行数、起止时间和字段完整性。

## 5. 功能需求与验收标准

### FR-01 四通道实时状态

页面显示设备编号、最新采集时间、累计接收量和四路最新值。

验收标准：任一有效记录到达后，四个当前值使用同一时间戳更新；通道名称、顺序和单位与统一配置一致。

### FR-02 趋势观察

提供总体趋势和单项趋势，长时间记录下限制图表绘制点数。

验收标准：新增数据按时间追加；切换通道不会改变原始记录；图表降采样不影响 CSV 导出记录数量。

### FR-03 状态分层

分别呈现数据服务、采集终端、数据时效和暂停显示状态。

验收标准：WebSocket 失败显示“数据服务未连接”；无 TCP 终端显示等待或离线；终端在线但超时无新数据时显示接收暂停；客户端暂停不应被显示为终端离线。

### FR-04 巡检记录

记录表按采集时间展示四通道数值，宽屏端支持较长会话，移动端侧重最近记录。

验收标准：表格最新时间与状态监测页一致；每行包含时间和四个字段；大数据量下只渲染当前页面或可见范围。

### FR-05 CSV 导出

用户可以导出当前客户端缓存中的记录。

验收标准：文件为 UTF-8；包含采集时间和四通道表头；导出不停止采集、不清空页面；导出行数与当前可导出缓存一致。

### FR-06 响应式 Web/PWA

宽屏端提供监测工作台，移动端提供单列近端查看，并共享同一数据服务。

验收标准：1366×768 下核心状态和趋势无需横向滚动；常见手机宽度下指标卡、导航和表格入口可操作；添加到主屏幕后仍能访问相同功能。

## 6. 数据要求

结构化记录至少包含：设备编号、采集时间、泄油口温度、泄油口压力、油口 A 压力和油口 B 压力。部署台账还应维护设备编号、终端编号、通道、测点位置和标定关系，但这些信息不通过公开作品版展示。

## 7. 风险与约束

- 采集值可能受传感器量程、安装、接线、标定、网络和工况共同影响。
- 四个通道量纲不同，不能根据同图曲线高低直接比较。
- 浏览器内存缓存和服务端最近记录都存在容量边界，必须建立导出纪律。
- 公开演示不得包含真实终端地址、服务器域名、现场数据或申报材料。

## 8. 后续规划

1. 将网络和设备参数迁移为部署配置，并加入配置校验。
2. 引入时序数据库和任务级巡检会话，支持可靠断点续传。
3. 补充工况标注、阈值版本管理和基于泵型的规则配置。
4. 建立采集完整率、丢帧率、端到端延迟和导出一致性测试。
